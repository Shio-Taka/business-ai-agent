# Business AI Agent

## 1. 概要

自然言語による指示から会議室の空き状況を確認し、ユーザーの確認後に会議室を予約するAIエージェントです。
予約日・時間・参加人数などの情報をAIが抽出し、必要に応じてTool Callingを行って会議室の検索・予約を実行します。
予約実行前にはユーザーに確認を行い、「はい」と回答された場合のみ予約を確定します。

## 2. 想定ユーザーと業務課題

- 想定ユーザー: 社内で会議室を利用する従業員
- 困っている業務: 会議室の予約時に、予約日・時間・参加人数などの情報を入力し、空き状況を確認する必要がある
- このエージェントで短縮・改善できること:
  - 自然言語による予約依頼から必要な情報を自動で抽出
  - 不足している情報をAIが確認
  - 会議室の空き状況を自動検索
  - ユーザーの確認後に予約を実行
  - 入力ミスや予約条件の不備を検証

## 3. 主な使い方

CLIから自然言語で会議室の予約内容を入力します。

### 起動

    npm run dev

### 入力例

    明日の14時から15時まで、5人で会議室を予約したい

AIが予約日・開始時刻・終了時刻・参加人数を抽出し、利用可能な会議室を検索します。

利用可能な会議室がある場合は、予約内容をユーザーに提示して確認します。

    この予約を実行しますか？（はい / いいえ）

「はい」と回答すると、`book_room` Toolが呼び出され、予約が実行されます。

## 4. デモシナリオ

### シナリオ1：正常な予約

#### 入力

    明日の14時から15時まで、5人で会議室を予約したい

#### 期待される処理

1. AIが予約日・開始時刻・終了時刻・参加人数を抽出
2. `get_available_rooms` Toolを呼び出す
3. 利用可能な会議室を取得
4. ユーザーに予約内容を確認
5. ユーザーが「はい」と回答
6. `book_room` Toolを呼び出す
7. 予約完了を表示

### シナリオ2：情報不足

#### 入力

    明日の会議室を予約したい

#### 期待される出力

    予約に必要な情報が不足しています。
    開始時刻、終了時刻、参加人数を教えてください。

不足している情報をユーザーから取得した後、予約処理を継続します。

### シナリオ3：参加人数が不正

#### 入力

    14時から15時まで、0人で会議室を予約したい

#### 期待される出力

    会議室の予約には、参加人数を1人以上の整数で指定していただく必要があります。

不正な入力の場合は会議室検索を実行しません。

### シナリオ4：利用可能な会議室がない

#### 入力

    13人で明日の14時から15時まで会議室を予約したい

#### 期待される出力

    利用可能な会議室がありません。

会議室の定員を超える場合は予約を実行しません。

## 5. アーキテクチャ

~~~mermaid
flowchart TD
    User[ユーザー] --> UI[CLI]
    UI --> Agent[AI Agent]
    Agent --> LLM[Gemini API]
    Agent --> GetRooms[get_available_rooms]
    GetRooms --> RoomData[会議室情報]
    RoomData --> Agent
    Agent --> Confirm[ユーザーへ予約確認]
    Confirm -->|はい| BookRoom[book_room]
    Confirm -->|いいえ| Cancel[予約中止]
    BookRoom --> Result[予約完了]
    Result --> User
~~~

### 各コンポーネントの役割

- **UI / CLI**:
  ユーザーから自然言語による予約依頼を受け取り、AIからの質問や予約結果を表示します。

- **Backend / Agent Runner**:
  TypeScriptで実装したAI Agentが、ユーザー入力の解析、予約情報の管理、Tool Calling、処理全体の制御を行います。

- **LLM API**:
  Gemini APIを利用し、自然言語から予約情報を抽出したり、不足情報の判断やTool Callingの判断を行います。

- **利用ツール**:
  `get_available_rooms`で利用可能な会議室を検索し、`book_room`でユーザー確認後に予約を実行します。

- **データ保存**:
  現在は簡易的な会議室情報をプログラム内で扱っており、外部データベースへの永続化は行っていません。

## 6. エージェントの処理フロー

1. ユーザーから自然言語による予約依頼を受け取る
2. LLMが予約日・開始時刻・終了時刻・参加人数などの必要な情報を抽出する
3. 情報が不足している場合は、AIがユーザーへ追加情報を質問する
4. 取得した予約情報を検証する
5. `get_available_rooms` Toolを呼び出して利用可能な会議室を検索する
6. 利用可能な会議室がない場合は、その旨をユーザーへ返す
7. 利用可能な会議室がある場合は、予約内容をユーザーへ提示して確認する
8. ユーザーが「はい」と回答した場合のみ`book_room` Toolを呼び出す
9. 予約結果をユーザーへ返す

## 9. 工夫した点

### 技術面

- **自然言語からの予約情報抽出**
  - 「明日の14時から15時まで、5人」のような自然な文章から、予約日・開始時刻・終了時刻・参加人数をAIに判断させています。

- **Tool Calling**
  - AIが必要に応じて`get_available_rooms`と`book_room`を呼び出す構成にしています。
  - LLMが文章を返すだけではなく、実際の処理をToolとして実行できるようにしています。

- **入力バリデーション**
  - 参加人数が0人の場合や、終了時刻が開始時刻より前の場合など、不正な入力を検証しています。

- **不足情報への対応**
  - 予約に必要な情報が不足している場合、AIが不足している項目を確認し、追加情報を取得して処理を継続します。

- **テスト**
  - Vitestを利用して会議室検索Toolのユニットテストを実装しています。
  - 5人の場合の検索、13人の場合の空室なし、0人の入力エラー、時間の逆転エラーをテストしています。

### 業務面

- **予約実行前のユーザー確認**
  - AIが自動的に予約を確定しないよう、予約実行前にユーザーへ確認を行います。
  - 「はい」と回答された場合のみ`book_room`を実行することで、意図しない予約を防止しています。

- **自然な入力への対応**
  - ユーザーが決められたフォームに沿って入力するのではなく、自然な文章で予約を依頼できるようにしています。

## 10. 制約・今後の改善

- うまくいくケース:
  - 予約日・開始時刻・終了時刻・参加人数が明確な自然言語入力
  - 会議室の定員以内での予約
  - 「明日」などの相対的な日付を含む予約
  - 必要な情報が不足している場合に追加情報を入力するケース

- 苦手なケース:
  - 曖昧な日時や複雑な予約条件
  - 実際のカレンダー情報との照合が必要なケース
  - 複数ユーザーが同時に同じ会議室を予約するケース
  - 自然言語だけでは判断できない複雑な業務ルール

- 未実装のこと:
  - データベースへの予約情報の永続化
  - Google CalendarやMicrosoft 365などのカレンダー連携
  - ユーザー認証・権限管理
  - 予約変更・予約キャンセル
  - 複数ユーザーによる同時予約への排他制御
  - Web UI

- 実務投入するなら次に改善すること:
  - 会議室情報と予約情報をデータベースで管理する
  - 社内カレンダーと連携して実際の空き状況を取得する
  - ユーザー認証と権限管理を追加する
  - 同時予約を防ぐための排他制御を実装する
  - Web UIを追加して非エンジニアでも利用しやすくする
  - 予約変更・キャンセルなどの業務フローにも対応する
